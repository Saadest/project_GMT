# Package reference

## `my_robot_interfaces`

`ament_cmake` package that generates custom interfaces with `rosidl`.

| File | Contents |
| --- | --- |
| `msg/PoseCommand.msg` | `float64 x, y, z, roll, pitch, yaw` + `bool cartesian_path` |

Generate/verify the interface after a build:

```bash
ros2 interface show my_robot_interfaces/msg/PoseCommand
```

## `my_robot_description`

Holds the robot model. Everything the rest of the stack needs about geometry
lives here.

| File | Purpose |
| --- | --- |
| `urdf/my_robot.urdf.xacro` | Root file; includes the three parts and the fixed `gripper_base_joint`. |
| `urdf/arm.xacro` | `base_link` → `tool_link` chain, six actuated joints, collision + visual geometry. |
| `urdf/gripper.xacro` | `gripper_base_link`, two prismatic fingers, mimic coupling. |
| `urdf/my_robot.ros2_control.xacro` | `<ros2_control>` block for `ros2_control` with `mock_components/GenericSystem`. |
| `urdf/common_properties.xacro` | Shared materials (`grey`, `blue`, `dark_green`, `light_green`). |
| `launch/display.launch.xml` | Model + `joint_state_publisher_gui` + RViz2. |
| `rviz/urdf_config.rviz` | RViz2 display configuration. |

### Joint table

| Joint | Type | Parent → child | Axis | Limits |
| --- | --- | --- | --- | --- |
| `joint1` | revolute | `base_link` → `shoulder_link` | `z` | −3.14 … 3.14 rad |
| `joint2` | revolute | `shoulder_link` → `arm_link` | `y` | 0 … 2.5 rad |
| `joint3` | revolute | `arm_link` → `elbow_link` | `y` | 0 … 2.5 rad |
| `joint4` | revolute | `elbow_link` → `forearm_link` | `z` | −3.14 … 3.14 rad |
| `joint5` | revolute | `forearm_link` → `wrist_link` | `y` | −1.57 … 1.57 rad |
| `joint6` | continuous | `wrist_link` → `hand_link` | `z` | — |
| `hand_tool_joint` | fixed | `hand_link` → `tool_link` | — | — |
| `gripper_base_joint` | fixed | `tool_link` → `gripper_base_link` | — | — |
| `gripper_left_finger_joint` | prismatic | `gripper_base_link` → `gripper_left_finger_link` | `x` | 0 … 0.06 m |

All actuated joints declare `effort="1000.0"` and `velocity="1.0"`, which are
placeholder values from modelling — tune them before driving real hardware.

## `my_robot_moveit_config`

MoveIt 2 configuration generated by the Setup Assistant (`.setup_assistant`
records the generator metadata and is installed with the package).

| File | Purpose |
| --- | --- |
| `config/my_robot.srdf` | Planning groups, named states, end effector, virtual joint, collision pairs. |
| `config/joint_limits.yaml` | MoveIt-side limits and velocity/acceleration scaling. |
| `config/kinematics.yaml` | KDL IK plugin for the `arm` group. |
| `config/moveit_controllers.yaml` | Maps `arm_controller` / `gripper_controller` to `FollowJointTrajectory`. |
| `config/ros2_controllers.yaml` | Copy of the controller configuration used by the demo launch. |
| `config/initial_positions.yaml` | Fake-system initial joint positions. |
| `config/pilz_cartesian_limits.yaml` | Cartesian limits for the Pilz pipeline (pre-configured, pipeline not enabled). |
| `config/moveit.rviz`, `config/my_robot_ros2_control.xacro`… | Visualisation and control xacro used by the demo. |
| `launch/*.launch.py` | `demo`, `move_group`, `moveit_rviz`, `rsp`, `spawn_controllers`, `static_virtual_joint_tfs`, `setup_assistant`, `warehouse_db`. |

> `moveit_controllers.yaml` and `ros2_controllers.yaml` describe the same two
> controllers. Rename in one place → rename in the other.

## `my_robot_bringup`

| File | Purpose |
| --- | --- |
| `launch/my_robot.launch.xml` | Single entry point for the whole stack. |
| `config/ros2_controllers.yaml` | `update_rate: 100`, `arm_controller` (6 joints, position), `gripper_controller` (1 joint, position), `joint_state_broadcaster`. |
| `config/my_robot_moveit.rviz` | RViz2 layout used with the full stack. |

Adding a controller means: declare it under `controller_manager.ros__parameters`
in `config/ros2_controllers.yaml`, add a `spawner` node in
`launch/my_robot.launch.xml`, and — if MoveIt should command it — add it to
`my_robot_moveit_config/config/moveit_controllers.yaml`.

## `my_robot_commander_py`

`ament_python` package. Entry points defined in `setup.py`:

| Executable | Module |
| --- | --- |
| `commander` | `my_robot_commander_py/commander_template.py` |
| `test_moveit` | `my_robot_commander_py/test_moveit.py` |

`commander_template.py` builds its `MoveItConfigsBuilder` from
`my_robot_moveit_config`, overrides the planning-scene monitor and pipeline
settings, then drives `PlanningComponent` for the `arm` and `gripper` groups.

## `my_robot_commander_cpp`

`ament_cmake` package. Two executables installed to `lib/my_robot_commander_cpp/`:

| Executable | Source | Purpose |
| --- | --- | --- |
| `commander` | `src/commander_template.cpp` | `MoveGroupInterface` for `arm` and `gripper`, same topic contract as the Python node. |
| `test_moveit` | `src/test_moveit.cpp` | Minimal plan/execute probe with a single-threaded executor. |

Both commanders publish/accept the topics documented in
[`interfaces.md`](interfaces.md).
